# 三国象棋三人联机试玩与部署

## 本机开发

```sh
npm ci
npm run dev
```

网页由 Vite 提供，联机服务默认监听 `127.0.0.1:3000`。在网页选择“联机对弈”，输入昵称后创建房间；另外两位玩家输入相同房间号加入，三人分别选择魏、蜀、吴并准备后自动开始。

联机魏方默认使用标准棋盘方向，蜀、吴默认使用旋转 180° 的视角；“翻转棋盘”仅改变个人看到的位置和点击、触摸换算。服务器棋局与棋谱始终保存标准坐标，不会因视角变化而修改。

第四人可在“观战”入口输入同一房间号，等待区、已开局和满员房间均可观看。观战者不占席位、不准备、不走棋，也不会收到玩家重连凭证；刷新或断线后按房间号重新获取公开局面。观战时可翻转棋盘和退出；房间销毁时显示提示。正在对局的玩家切换去观战时沿用退出确认，确认退出会先按既有规则认输。

等待区可点击明显的“退出房间”，退出者的席位和凭证立即失效；最后一人退出后房间删除。等待区断线会取消准备，席位保留 60 秒供刷新重连，之后自动释放；在线玩家也可点击离线玩家旁的“释放席位”。只有三人都在线并各占一个阵营、全部准备，才会开始对局。

断网时仍可退出：本机立即返回大厅并清除旧房间地址，退出通知在连接恢复后补发；页面会显示服务器是否确认。开局后独立的“认输”按钮让本国出局并按顺序确定名次，仍可留在房间观看；主动退出则先认输再离开。出局者退出不重复结算。短暂断线不会自动认输，开局后不能释放其他人的席位。

## 生产启动

```sh
npm ci
npm run build
npm start
```

可通过环境变量设置监听地址与端口：

```text
HOST=127.0.0.1
PORT=3000
NODE_ENV=production
```

健康检查：`GET /three-chess/api/health`。正常响应会明确返回 `storage: "memory"`。

## 进程守护

仓库中的 `deploy/three-chess.service` 是当前线上使用的 systemd 配置。Node.js 24.22.1 安装在 `/opt/three-kingdoms-chess/runtime/node-v24.22.1-linux-x64`，应用版本放在 `/opt/three-kingdoms-chess/releases/`，`current` 软链接指向正在运行的版本。服务只监听本机 `127.0.0.1:3000`。切换 `current` 后：

```sh
sudo cp deploy/three-chess.service /etc/systemd/system/three-chess.service
sudo systemctl daemon-reload
sudo systemctl enable --now three-chess
sudo systemctl status three-chess
```

## nginx

`deploy/nginx-three-chess.conf` 是当前线上使用的 Nginx 片段。它只接管 `/three-chess/`，将网页、健康接口、Socket.IO 长轮询与 WebSocket 转发到本机 Node.js 服务。已有站点的其他路径不需要改动。

更新后执行：

```sh
sudo nginx -t
sudo systemctl reload nginx
```

## 数据边界

- 正式棋局只由服务器内存中的房间状态决定，客户端不能上传棋盘、身份或胜负结果。
- 重连凭证有 256 位随机熵并只保存在对应浏览器本地；昵称不能用于抢回席位。
- 同一凭证建立新连接时，旧连接会被替换，房间内仍只有一个席位。
- 服务器重启后所有房间消失；首版没有数据库持久化，也不会声称已经持久保存。
