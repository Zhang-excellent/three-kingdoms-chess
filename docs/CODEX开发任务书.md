# 三国象棋 · Codex 开发任务书

## 现在从哪里开始

这是一个可运行的 Vue 3 + TypeScript 基线项目。本轮已完成同屏棋盘与走子，下一步是在你的电脑上运行、验收，再调整你发现的问题。

先把启动包解压，让 Codex 在这个项目目录工作。如果你已经克隆 GitHub 仓库，合并本包源文件到该仓库，保留原来的 `.git`、Word 规则和图片。随后将下面的指令直接交给 Codex。

## 界面验收要求

- 当前主公头像、卡片和“轮到某某行棋”文字一致；初始轮到曹操。
- 选中棋子有明显反馈，点本方另一子可以改选，重复点同一子可以取消。
- 落点提示与规则一致；敌方目标显示吃子标记；盟友目标不可吃、不可占。
- 成功走子后棋子位置、回合、头像、上一手痕迹、棋谱一次性更新。
- 非法走子/错误回合只能提示原因，不能推进回合或增加棋谱。
- 出局时全部棋子消失，子力数归零，卡片标记出局；轮次跳过出局方。
- 棋局结束后停止走子，显示胜方，允许本地悔棋复盘或重开。
- 上一手保留到下一次成功走子；点击或错误操作不能覆盖这条痕迹。
- 浏览器刷新能恢复当前局面与回合；本机存储不可用时不阻断走子。

## 规则仍待作者决定

1. 是否要求应将、禁止送将以及将死判负。
2. 如果采用上述规则，三人行动次序下的检查时点。
3. 两方重复判和的次数、是否要求相同下一行棋方和三方重复的处理。

遇到这些内容时，保持临时试玩模式，不替作者确定最终规则。

## 下一阶段：三台设备联机

在作者验收棋盘与规则后，再执行下一阶段：

- 新增 Java + Spring Boot 后端；一个房间管理一局棋。
- 创建房间、房间码加入、三国席位、玩家身份与准备开始。
- 后端保存权威棋局状态，核验玩家身份、轮次、目标位置与合法走法。
- 客户端发送移动意图；后端接受后广播完整状态或带版本的更新。
- 状态广播同时更新三个客户端的棋盘、头像、轮次、上一手和胜负。
- 使用棋局版本号与请求标识处理过期请求、重复发送、连续点击和并发操作。
- 玩家断线后可恢复身份，重连后取得当前棋局状态。
- 后端重新实现并测试规则校验，不能只相信前端校验。
- 联机悔棋、重开与和棋需要明确所有玩家的同意流程，不能沿用同屏按钮的单方行为。

先做小规模内存房间；持久化、账号和长期棋谱作为后续任务。完成后，把真实运行方法、接口与验证结果更新到 README。
