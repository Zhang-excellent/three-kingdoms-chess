# 三国象棋账号、历史对局与数据备份

## 当前范围

账号用于保存玩家身份和固定昵称，并为联机历史对局提供稳定的内部用户 ID。用户名就是昵称，注册后暂不支持修改。积分、得分率、排行榜、收藏、完整战绩统计和后台管理页面尚未实现。

游客不需要注册，仍可创建或加入房间、本地试玩和观战。游客席位有“游客”标识；即使游客昵称与某个账号相同，也不会自动合并身份或归入该账号，也不提供跨设备游客历史。

## 登录与期限

- 登录和注册位于首页右上角；注册成功后自动登录并返回原来的页面或邀请目标。
- 当前不提供找回密码入口。注册处提示“请记住密码，当前暂不提供找回”。
- 勾选“7 天免登录”时，会话从登录成功起有效 7 天。
- 不勾选时，服务端会话最长有效 12 小时，Cookie 不设置持久 `Max-Age`，关闭浏览器即结束。
- 主动退出只撤销当前会话。修改密码会验证当前密码，撤销该账号的全部旧会话并为当前操作签发新会话。
- 旧数据库中的恢复码字段保留但不重建、不清空；当前版本不提供恢复码生成、展示或使用的 HTTP 接口。

## 最近对局

- 只有正常开局并最终结束的联机对局才写入历史。未开局散房、取消准备、纯观战、本地试玩和导入复盘不计入。
- 每盘棋在开局时获得稳定的 UUID 对局 ID；同一房间“再来一局”会产生新的局次和新的对局 ID。
- 服务端保存开始/结束时间、房间号、规则版本、初始局面、参与者用户 ID 与当时昵称、阵营、完整走法、出局/认输/退出/超时事件、终局原因、最终局面和各方结果。
- 一盘棋只保存一份完整记录，通过 `game_participants` 关联多个账号。中途出局或退出的账号仍保留参与关系，整盘结束后可查看。
- 个人中心按结束时间倒序显示最近 5 盘；更早记录不删除。游客、未参与者、其他账号和未登录请求不能读取私人对局详情。

## 身份边界

登录 Cookie 只保存随机会话令牌，服务端通过数据库中的会话摘要验证账号。Socket.IO 握手和后续房间操作都从同一 HttpOnly Cookie 重新验证账号；账号昵称以服务端用户记录为准，不采用客户端提交的昵称或用户 ID。

账号玩家恢复房间席位时必须保持同一账号。游客房间 Token 是独立的重连凭证，不会把旧游客席位转换成账号席位。打开个人中心不会退出房间；从个人中心进入历史复盘时，如果仍占用联机席位，会按现有退房/认输确认流程处理。

## 配置与注册限流

本地默认数据库为项目根目录下的 `.data/auth.sqlite`，已加入 `.gitignore`。复制 `.env.example` 为 `.env` 可覆盖：

```text
THREE_CHESS_DATA_DIR=./.data
THREE_CHESS_COOKIE_SECURE=0
TRUST_PROXY=0
THREE_CHESS_REGISTER_LIMIT=20
THREE_CHESS_REGISTER_WINDOW_MINUTES=60
THREE_CHESS_LOGIN_LIMIT=10
THREE_CHESS_LOGIN_WINDOW_MINUTES=15
```

注册限流按服务端看到的客户端 IP 计算，默认每 60 分钟最多 20 次注册请求，以兼顾宿舍、校园和共用公网 IP；它不是“一 IP 一账号”，也不采集浏览器指纹。调大窗口或次数时仍保留服务端上限。

生产环境使用：

```text
THREE_CHESS_DATA_DIR=/opt/three-kingdoms-chess/data
THREE_CHESS_COOKIE_SECURE=1
TRUST_PROXY=1
```

Cookie 路径固定为 `/three-chess`，因此同一站点其他应用不会收到登录 Cookie。生产环境必须通过 HTTPS，确保 `Secure` Cookie 正常发送。

## 备份

SQLite 使用 WAL。为获得一致的完整备份，先停止服务，再归档整个数据目录：

```sh
sudo systemctl stop three-chess
sudo tar -C /opt/three-kingdoms-chess -czf /var/backups/three-chess/accounts-$(date -u +%Y%m%dT%H%M%SZ).tar.gz data
sudo systemctl start three-chess
```

备份文件包含账号、会话、历史对局和参与关系，应按敏感数据保管，不要提交到 Git 或公开分享。部署更新不得用本地测试数据库覆盖线上数据目录。

恢复时停止服务，将数据目录恢复到 `/opt/three-kingdoms-chess/data` 并重新设置权限，再启动服务：

```sh
sudo systemctl stop three-chess
sudo tar -C /opt/three-kingdoms-chess -xzf /var/backups/three-chess/accounts-YYYYMMDDTHHMMSSZ.tar.gz
sudo chown -R www-data:www-data /opt/three-kingdoms-chess/data
sudo chmod 700 /opt/three-kingdoms-chess/data
sudo systemctl start three-chess
```

## 表结构与迁移

- `auth_users`：内部用户 ID、显示昵称、唯一化昵称键、密码哈希、兼容保留的旧恢复码字段和时间戳。
- `auth_sessions`：Cookie 令牌摘要、关联用户 ID、创建时间和绝对过期时间。
- `game_records`：每盘棋唯一 ID、房间与局次、开始/结束时间、规则版本、初始/最终局面、参与者快照、走子、事件、终局原因与步数；`(room_code, room_round)` 唯一。
- `game_participants`：对局与账号的多对多参与关系，以及当时昵称、阵营、结果和是否出局；同一盘完整棋谱不会按玩家重复保存。

数据库连接时按 `PRAGMA user_version` 自动迁移到版本 `3`。已有账号、会话和旧恢复码字段原样保留；迁移只新增对局表与索引。发布归档不包含 `.data/`，版本切换不会清空持久数据。
