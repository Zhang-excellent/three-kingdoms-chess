# 三国象棋 · Three Kingdoms Chess

> 三人同局，魏蜀吴对弈。曹操独战，刘备与孙权结盟。

**三国象棋在线对弈平台**，基于中国象棋设计三方参与、两队对抗的玩法：保留方正棋盘，调整初始布局、主公活动范围和部分棋子走法，探索新的攻防与合作策略。

**当前阶段：规则设计与第一版开发准备。** 在线对弈功能尚未完成，首版将邀请朋友试玩，再根据实战反馈修改规则和软件。

## 项目想法

三名玩家分别控制魏、蜀、吴三个国家。魏方拥有完整的传统象棋子力，蜀吴两方组成联盟，共同对抗魏方。

子力数量、行动顺序与胜利目标各不相同。双方是否平衡，需要通过实际对局检验；规则会随试玩结果持续调整。

本项目也用于练习规则建模、Java 后端开发、实时通信与完整网站开发，并在 GitHub 记录开发过程。

## 棋盘与阵营

使用 **9 路、10 条横线**的象棋棋盘，棋子位于交叉点上，河界文字为 **“秦岭淮河”**。

| 阵营 | 主公 | 颜色 | 初始位置     | 初始子力 |
| ---- | ---- | ---- | ------------ | -------- |
| 魏   | 曹操 | 红色 | 棋盘下方     | 16 枚    |
| 蜀   | 刘备 | 黑色 | 棋盘上方左侧 | 7 枚     |
| 吴   | 孙权 | 绿色 | 棋盘上方右侧 | 6 枚     |

上方两翼主体布局互为镜像，**上方正中的卒归蜀方控制，保持黑色**。全盘共 29 枚棋子。

## 走子顺序

**曹操 → 刘备 → 孙权 → 曹操……**

每位玩家在自己的回合移动本国一枚棋子，完成一步后交给下一位玩家。蜀或吴出局后，跳过其回合，由曹操与剩余一方交替行棋。

## 首版玩法

### 主公走法

| 主公 | 走法                   | 活动范围                         |
| ---- | ---------------------- | -------------------------------- |
| 曹操 | 每步沿横线或竖线走一格 | 下方九宫                         |
| 刘备 | 每步向左或向右走一格   | 上方底线第 2 至第 8 路，包含两端 |
| 孙权 | 每步向左或向右走一格   | 上方底线第 2 至第 8 路，包含两端 |

路数按初始棋图从左至右编号。刘备、孙权共用这段底线，且不能占据对方或其他棋子已有的位置；上方九宫斜线不限制两位主公。

### 特殊棋子：锋

锋的移动位置也是吃子位置，目标交叉点存在敌方棋子时，可以按相同走法吃掉。

| 方向 | 一步可走的距离 |
| ---- | -------------- |
| 向前 | 1 格或 2 格    |
| 向后 | 1 格           |
| 向左 | 1 格           |
| 向右 | 1 格           |

- 不能斜走，不能跳子。
- 向前走两格时，中间交叉点必须为空。
- 不能落在本方或盟友已有棋子的交叉点上。
- 初始棋图中，蜀吴的前进方向为向下；翻转显示棋盘不会改变真实走法。
- 锋按自身走法吃子，不使用炮的隔子吃子规则。

### 其他棋子

未另行修改的棋子，沿用中国象棋的基本移动与吃子方式。

| 棋子   | 基本走法                                                     |
| ------ | ------------------------------------------------------------ |
| 车     | 沿横线或竖线移动任意格数，中间不能有棋子                     |
| 炮     | 不吃子时沿直线移动且不能跳子；吃子时，炮与目标之间必须恰好隔一枚棋子 |
| 马     | 走日字，遵守蹩马腿限制                                       |
| 相、象 | 斜走两格，遵守塞象眼限制，不能过河                           |
| 仕、士 | 在本方九宫内斜走一格                                         |
| 兵、卒 | 过河前向前走一格；过河后可向前、向左或向右走一格，不能后退   |

魏方朝上前进，蜀方与吴方朝下前进。河界仍用于判定兵卒过河和相象的活动范围。

### 蜀吴联盟与炮架

- 蜀吴互不吃子。
- 所有棋子均不能落在本方或盟友已经占据的交叉点上。
- 盟友棋子也会形成行棋阻挡，不能因结盟而穿过。
- **任何阵营、任何种类的棋子都可以作为炮架，包括主公。**

### 胜负与出局

| 局面                         | 结果                                             |
| ---------------------------- | ------------------------------------------------ |
| 曹操被吃掉或魏方困毙         | 魏方失败，蜀吴联盟共同获胜                       |
| 刘备或孙权被吃掉，或该国困毙 | 该国出局，全部棋子立即清空；剩余盟友继续对抗魏方 |
| 蜀吴两国均出局               | 魏方获胜，蜀吴联盟失败                           |

**困毙**：轮到某国行棋时，该国所有棋子均无合法走法，按主公死亡处理。

出局国家的棋子清空后，不再构成阻挡或炮架。

### 取消对面笑杀法

主公可以在同一路上照面，不因照面判负。主公吃子仍须符合自身走法和活动范围，不能沿整条线路远距离吃掉另一位主公。

### 重复和棋与待确认细节

当前约定为 **“两方重复不变作和”**。以下细节仍需明确：

- 重复多少次判和，以及是否要求相同行棋方。
- “两方”是否仅指剩余两国，或也包括三国在场时两方的重复。
- 三国共同重复局面的处理方式。
- 是否沿用不得送将、必须应将和将死判负。
- 三方轮流行动时，应将与将死的判定时点。

以上内容属于首版玩法草案，后续确认的规则会继续更新到文档与实现中。

## 计划采用的技术

以下为初步技术方案，具体选择会随开发调整。

| 部分     | 计划方案           | 用途                         |
| -------- | ------------------ | ---------------------------- |
| 前端     | Vue 3 + TypeScript | 棋盘、房间与玩家交互         |
| 后端     | Java + Spring Boot | 房间管理、规则校验与对局控制 |
| 实时通信 | WebSocket          | 同步行棋、轮次和对局结果     |
| 数据库   | MySQL              | 保存对局与行棋记录           |

三名玩家进入**同一个网站、同一个房间**，分别执掌魏、蜀、吴。

后端保存正式棋局状态，收到走棋请求后校验玩家身份、轮次和走法，再将结果同步给房间内的玩家。

## 试玩与迭代

首版完成后，将邀请熟悉象棋的朋友进行测试，并轮换阵营，记录规则版本、行棋过程与结果。

重点观察：

- 魏方与蜀吴联盟的胜负表现。
- 先后手和联盟连续行动对攻防的影响。
- 锋的实战价值、初始布局和主公活动范围是否合理。
- 是否存在规则歧义、重复拖延或难以处理的局面。
- 棋盘操作、轮次提示与网络同步是否顺畅。

每轮尽量只调整少量规则，保留修改原因和测试反馈，方便比较不同版本。
