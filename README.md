# 三国象棋 · V0.2 三人房间联机试玩

三人同局，魏、蜀、吴独立竞争。最后存活的一方获胜，其余两方失败；联机中也可由存活各方一致同意和棋。

项目同时提供本地试玩和三人房间联机。当前规则仍是试玩规则；联机服务使用 Node.js、TypeScript 与 Socket.IO，并直接复用前端使用的纯规则引擎。账号、固定昵称和可撤销登录会话使用持久 SQLite 保存；游客仍可直接进入大厅和房间。

手动部署前应核对服务器当前提交与更新脚本的基线；本地构建产物位于 `dist/`。

网站默认进入游戏首页，可从首页进入公开对战大厅、好友对战、其他玩法和本地试玩。创建或加入三人房间后会直接进入完整棋盘，选阵营、准备、邀请、对局和再来一局都在同一棋盘页面完成。玩家在等待或对局中主动通过站内导航离开房间时，会先完成服务端退房；等待阶段直接释放席位，进行中的存活玩家按认输出局。刷新、短暂断网和切到后台仍保留重连席位。

## 启动试玩

环境：Node.js `^22.18.0` 或 `>=24.12.0`。

```sh
npm ci
npm run dev
```

打开终端显示的 Vite 地址。`npm run dev` 会同时启动网页和本机联机服务；网页通过 `/three-chess/socket.io` 连接服务端。

需要复验首页四入口、精简导航、登录昵称入口和桌面/手机布局时，可用测试模式启动服务后执行 `npm run accept:home`。脚本会生成普通桌面、高屏整页和手机截图：`2026-11-19-home-desktop.png`、`2026-11-19-home-tall.png` 与 `2026-11-19-home-mobile.png`。

需要复验中国象棋单棋桌的桌面、手机和双人联机流程时，保持 `npm run dev` 运行，在另一个终端执行 `npm run accept:chinese`。脚本使用本机 Chrome 或 Edge 的独立临时配置启动三个真实浏览器会话，并把截图写入 `docs/验收截图/中国象棋-*.png`；不会使用或改动日常浏览器配置。

需要复验五兵联盟和马棋的单棋桌、实时走子、访客只读与手机布局时，保持 `npm run dev` 运行，在另一个终端执行 `npm run accept:other-games`。脚本会分别启动独立浏览器会话并生成 `docs/验收截图/五兵联盟-*.png` 与 `docs/验收截图/马棋-*.png`。

需要复验斗兽棋联机棋桌、双方准备、实时走子、自动视角、落子音效、访客观战、提和、再来一局、认输、退出和手机布局时，保持 `npm run dev` 运行，在另一个终端执行 `npm run accept:beast`。脚本会生成 `docs/验收截图/斗兽棋-联机棋桌-空桌.png`、`斗兽棋-联机-对局.png`、`斗兽棋-联机-上方视角.png`、`斗兽棋-联机-和棋.png` 与 `斗兽棋-手机-联机对局.png`。

需要复验迷雾象棋的服务端分视角、双方入座、准备、走子、刷新恢复、吃将终局、同房再来一局和手机布局时，保持 `npm run dev` 运行，在另一个终端执行 `npm run accept:mist`。脚本会生成 `docs/验收截图/迷雾象棋-*.png`。

需要复验三国象棋创建房间后直接进入棋盘、三人阵营准备、同页开局、左侧菜单和手机布局时，保持 `npm run dev` 运行，在另一个终端执行 `npm run accept:three-kingdoms`。脚本会以真实 Chromium 页面配合两个独立 Socket.IO 客户端完成三人开局，并生成 `docs/验收截图/三国象棋-*.png`。

账号数据库默认写入项目根目录下被 Git 忽略的 `.data/auth.sqlite`。需要覆盖端口、数据目录或 Cookie 策略时，将 [.env.example](.env.example) 复制为 `.env`；服务启动时会读取该文件。

只体验不联网的本地模式，也可直接用 Chrome、Edge 等现代浏览器打开 **preview/试玩.html**。棋盘网页是单文件离线产物，音乐与音效文件另放在 **preview/audio/**；联机模式必须通过上述服务或已部署网站使用。

点击当前阵营的棋子，查看可走位置，再点击目标交叉点。圆点代表可走位置，红圈代表可吃子。走子后，下一位主公的头像亮起，棋盘保留上一手的起点、落点和方向。

## Android APK

Android 使用 Capacitor 8，默认 WebView 来源为 `https://localhost`。`src/network-config.ts` 统一判断运行环境：网页继续使用 `/three-chess/api/...` 和 `/three-chess/socket.io` 相对路径；原生 Android 使用 `https://47.95.251.153`、`credentials: include` 与 `withCredentials: true`。服务端返回的 `/three-chess/api/avatar/...` 头像地址也会在原生端转换为生产服务器完整网址，游客内置头像仍使用 App 本地资源。账号仍使用服务端 Session Cookie，没有改成 JWT。

服务器只为白名单来源处理跨域：`https://localhost`、`https://47.95.251.153`，开发模式下另允许本机 Vite 地址。Android 来源的登录、注册、改密和新会话 Cookie 使用 `HttpOnly; Secure; SameSite=None; Path=/three-chess`，网页来源继续使用 `SameSite=Lax`。Socket.IO 同时校验 CORS 和握手来源。

重新生成 Android 工程资源并编译调试 APK：

```powershell
cd "C:\Users\lenovo\Documents\ChatGPT\三国象棋"
npm ci
npm run check
npm test
npm run build
npx cap sync android
cd android
.\gradlew.bat assembleDebug
```

如系统默认 `JAVA_HOME` 是 Java 8，需先切换到 JDK 17～24；本机已安装的 JDK 21 通常位于 `%USERPROFILE%\.jdks\jbr-21.0.11`。手动编译时可在 `android` 目录执行：

```powershell
$env:JAVA_HOME="$env:USERPROFILE\.jdks\jbr-21.0.11"
$env:Path="$env:JAVA_HOME\bin;$env:Path"
.\gradlew.bat --no-daemon assembleDebug
```

分享用调试 APK 可运行 `npm run android:apk` 生成。命令会完成网页构建、Capacitor 同步、自动选择 JDK 17～24 和 Android 编译，并自动写出两个便于查找的同名文件：

- 项目根目录：`three-chess.apk`
- `android/app/build/outputs/apk/three-chess.apk`

Gradle 内部的 `android/app/build/outputs/apk/debug/app-debug.apk` 仍会作为中间产物存在，但不需要进入 `debug` 目录查找或重命名。发布签名 APK 需先按自己的 Android 签名配置生成 Keystore，再执行 `.\gradlew.bat assembleRelease`；项目不会提交私钥或签名密码。

## 已实现

- 9 路、10 横线棋盘，河界为秦岭与淮河，29 枚初始棋子：魏 16、蜀 6、吴 7；曹操视角上方左吴右蜀，河界左侧淮河、右侧秦岭，中路中卒归吴方。
- 魏红、蜀黑、吴绿；三方存活时按曹操 → 刘备 → 孙权三拍循环行棋，每方每回合一步。
- 全部棋种的移动、阻挡和吃子校验，含锋与主公的特殊规则。
- 任意两个不同阵营可按棋子走法互吃，同国棋子不可互吃；任意棋子可作炮架。
- 任意主公被吃、本国困毙或认输后失败并清空子力；其余两国严格交替，最后存活的一方获胜。
- 联机中只有当前行棋的存活方可提和，提出者自动同意；其余存活阵营全部同意后判和，任一拒绝则继续。已有一方出局时由剩余两方表决。
- 选中棋子反馈、合法落点与吃子提示、当前头像高亮、上一手痕迹和行棋记录。
- 新访客首页包含三国阵营介绍、房间恢复入口和“公开大厅 → 好友对战 → 其他玩法 → 本地试玩”四个同权重大标题入口；入口使用统一米白卡片和朱红、深赭金、松石绿、墨青灰标题色，不展开完整棋盘，也不增加说明段落、装饰小字或虚假状态。
- 顶部导航新增“其他玩法”，入口页展示“五兵联盟”“马棋”“中国象棋”“迷雾象棋”和“斗兽棋”五个选择框，为后续其他棋种保留独立扩展空间。
- 其他玩法采用棋社式“棋桌 → 棋盘”两层流程：进入任一棋类先看到左右红黑席位和中央棋桌，点击空席位入座后才进入棋盘；已入座的头像框变蓝，对局开始后中央棋桌变蓝并可点击旁观。账号头像或统一的游客企鹅头像会显示在棋桌、等待区和对局头像中。
- 五兵联盟是独立双人单棋桌玩法：红方为五兵、双士、双象和主帅共 10 子，黑方为标准 16 子；红方每回合连续走两步，黑方每回合走一步，不强制应将，吃掉对方将帅立即获胜。玩家入座后在同一棋盘的中央卡片选择“开始”或“取消开始”，邀请好友与开始按钮并列；左侧箭头菜单提供提和、认输和离开。双方开始后进入正式对局，访客仅可旁观。
- 五兵联盟复用木色棋盘、圆形棋子、权威落子、上一手、棋谱、翻转、认输、退出和同房间再来一局；已开局的新访客可查看服务端实际盘面但不能走棋或重开。主动导航离开会立即退房；切换标签页、锁屏或网络短暂中断只进入 60 秒重连保护。
- 马棋是独立双人单棋桌玩法：双方各九马，红方先行，马走日且受马腿阻挡，先踏入对方中央底线帅位的一方获胜。棋桌选座、中央开始/邀请、左侧对局菜单、访客旁观、终局和同房间再来一局均与五兵联盟、中国象棋保持一致。
- 中国象棋为第三个独立双人单棋桌玩法：先在棋桌选择红方或黑方，入座后显示经典 32 子棋盘。规则包含九宫、马腿、象眼、炮架、过河兵、将帅照面、不得送将、将死与困毙判负。玩家入座后可把空对手席切换为“神秘老人 · 软件对手”，真人执红或执黑均可；后台引擎执红时服务端自动走第一步。玩家界面统一使用“神秘老人”名称和专属头像，后台仍由外部皮卡鱼 UCI 子进程运行，默认单线程、64 MiB Hash、每步 800 ms、全站同时计算一局，并对旧对局结果、超时和并发队列做隔离。正式落子后播放与三国象棋一致的落子/吃子音效；服务端保存完整棋谱，登录玩家可在“我的账号 → 中国象棋”查看最近 5 盘并逐手复盘。前三种联机棋桌玩法均支持双方同意和棋，人机对局暂不提供提和。
- 迷雾象棋为第四个独立双人单棋桌玩法：复用中国象棋棋盘、棋子与基础走法，红方全局第一手禁炮、其余棋子不限，第二手起恢复炮法；不强制应将并允许送将和将帅照面，实际吃掉将帅获胜。服务端为红黑双方分别生成视野，只发送己方棋子、全部可走可吃落点和该格敌棋；进行中隐藏对手走子轨迹与完整棋谱，终局后才向本局双方揭晓全盘。落子和己方可见损失播放与三国象棋一致的音效，不使用隐藏攻击者信息；观战者进入棋桌后直接查看无迷雾完整实时棋盘和完整棋谱。断线席位沿用 60 秒重连保护。
- 斗兽棋为第五种联机双人玩法：沿用单棋桌模式，点击下方或上方空席位并入座，双方准备后开局。使用用户提供的木质 7×9 原图棋盘，棋子按棋种统一着色，其中狗改为垂耳、短口鼻犬类侧影，猫改为尖耳、胡须的正面坐姿；支持鼠入河、狮虎跳河、陷阱降级、兽穴与困毙胜、三次重复及 100 半回合和棋。上方玩家自动获得本方子力在下方的翻转视角，非当前回合不会变暗；服务端确认新走棋后播放与三国象棋一致的落子/吃子音效。页面左上固定显示提和、认输、退出，访客可点击进行中棋桌观战；结束后保留双方席位并可在原桌再来一局。
- 五兵联盟、马棋、中国象棋、迷雾象棋和斗兽棋统一使用 60 秒断线重连保护：页面进入后台、切屏、锁屏、网络波动或 Socket 临时断开时不会立即认输或释放席位；其他玩家看到“断线中”，期限内恢复原身份和最新局面会取消清理。超过 60 秒才释放席位，进行中的存活玩家此时按现有认输规则结算。主动通过站内导航离开仍立即退房。
- 三国象棋主玩法改为同一棋盘内等待：创建或加入房间立即显示完整 29 子棋盘，三名玩家通过左侧头像选择魏、蜀、吴，在棋盘中央的等待层执行“开始/取消开始”和复制邀请链接；三人到齐并全部开始后，等待层消失，同一页面进入正式对局，不跳转独立等待页。
- 公开对战大厅采用棋社式 10 桌视图：第 1 桌是无需创建、始终可加入的“公开房间”，其余 9 桌由玩家点击空桌创建；每桌按曹操、房间号/状态、刘备、孙权四栏展示。
- 三个阵营席位均可点击，弹框只要求可选的“昵称：”；加入已有房间时直接坐到所点阵营，空桌则同时输入 6 位房间号后创建并入座。
- 有人入座或创建后桌子点亮，显示昵称、房间号、人数和加入/观战操作；对局中或已结束时点击中间区域、或点击“观战”进入只读对局。
- 创建房间时可选择是否在大厅展示，默认展示；未展示房间仍可通过准确房号、邀请链接和观战入口进入。
- 棋盘等待层可复制由当前运行地址和服务器确认房间号生成的完整邀请链接；链接只包含 `mode=online` 与 `room`，不携带重连凭证。自动复制失败时弹窗显示可全选、长按复制的完整网址。
- 好友打开邀请后会先向服务器查询房间：等待中的房间可直接选择空阵营并加入，昵称可留空；满房、已开局或已结束房间显示状态和观战入口，失效房间只提供返回大厅。已有其他房间的玩家不会被自动退房或覆盖身份。
- 首页、大厅、好友对战和同一棋盘房间流程使用独立页面状态；顶部导航统一使用“好友对战”且不再重复放置独立“观战”，好友对战页内部继续保留观战入口。所有主动离开房间的站内导航统一先完成服务端退房，包括顶部导航、网站标题、棋盘菜单和浏览器后退。设置、玩法说明、昵称弹窗及同房间开局、结果、再来一局切换不会退房。
- 有行棋记录后可从本地、联机或观战页面导出 Markdown 棋谱；文件包含规则版本、导出时间、胜负、标准显示坐标走法，以及初始和导出时全部子力位置。
- 本地试玩提供“自由试玩 / 录谱”和“棋谱复盘”切换；可导入当前或旧版导出棋谱，按完整局面快照执行初始、上一步、下一步、跳步、自动播放及慢/正常/快三档调速，步进控件位于棋盘下方，所有复盘操作不会覆盖本地对局存档。
- 新版导出棋谱附带版本化 JSON，记录坐标约定、初始/最终子力、完整走法、真实出局、认输、和棋与终局事件，并单独保存和棋结束前的待行棋方；导入优先使用结构化数据，同时兼容旧版纯文字棋谱。
- 首页右上角提供“登录 / 注册”，未登录也可继续浏览大厅和以游客身份对弈。注册用户可在个人中心上传方形头像，浏览器会居中裁切并压缩为不超过 300KB 的 PNG、JPEG 或 WebP；头像会保存在服务端账号数据库，并用于公开大厅、三国象棋席位及三种其他棋类对局。游客统一显示内置企鹅头像。个人中心还包含账号昵称与最近对局，账号设置按需展开，当前不提供找回密码入口。
- 用户名即昵称，支持中文、英文字母、数字和下划线，规范化为去首尾空格、Unicode NFKC 和英文小写后唯一；密码明确允许 4～64 个字符。注册处提示用户记住密码。
- 账号会话使用服务端持久会话表与 HttpOnly Cookie。勾选“7 天免登录”时有效 7 天；不勾选时服务端最长有效 12 小时，浏览器关闭后 Cookie 也会结束。退出或改密会撤销旧会话。Android Capacitor 通过受限 CORS、`SameSite=None; Secure` Cookie 和 WebView 第三方 Cookie 支持复用同一 Session 服务。
- 登录账号进入房间时，昵称由服务端根据 Cookie 会话确定，客户端提交的昵称或用户 ID 不能覆盖账号身份。游客席位显示“游客”标识，旧游客席位不会因昵称与账号相同而自动归入账号。
- “我的账号”直接显示“三国象棋”“迷雾象棋”两个棋谱目录。每个目录独立按结束时间倒序展示该玩法最近 5 盘，显示时间、对手、己方阵营、结果和步数；三国象棋继续使用原有复盘，迷雾象棋使用无迷雾全盘复盘，并提供初始局面、上一步、下一步、最后一步和返回列表。
- 悔棋、重新开局、独立的背景音乐与木质落子音效设置、带规则版本、胜负及轮次位置的本机自动保存，以及键盘 Enter/空格操作。旧名次、联盟、四拍或旧初始布局存档保留原数据并提示另开新局。
- 桌面与手机宽度的布局适配。
- 本地试玩与联机对弈模式切换；创建房间须自定未占用的 6 位纯数字房间号，前导零保留。加入和观战严格按所填房间号进入；旧的 6 位字母数字房间号可继续用于已有房间的加入、观战和重连。
- 对局结束后任一房内玩家可点“再来一局”，原房间号、玩家及阵营保留，准备状态全部清空；同一棋盘会重新显示等待层，并保留上一局结果、导出棋谱和可展开棋谱。三人重新开始后才进入新棋局。有人退出时，剩余玩家继续在棋盘等待层补位。
- 服务器权威保存房间、身份、阵营、棋局、精确轮次位置、出局、棋谱和结果；客户端只提交走棋意图。
- 房间内串行处理、局面版本号和请求唯一编号，拒绝越权、非法、重复和过期请求。
- 高熵重连凭证、断线保留座位、刷新完整同步，以及同一身份新连接替换旧连接。
- 棋盘等待阶段主动离开会立即释放席位、阵营、准备状态和凭证，空房间自动删除。等待阶段断线会取消准备并保留 60 秒；在线对局和已结束房间断线保留 180 秒，重连会取消清理任务，超时后按当前阶段安全离席。
- 断网时退出立即回到本机大厅并清理旧房间地址；服务器恢复后补发退出通知。房间号以用户提交且经服务端确认的编号为准。
- 开局后可认输并判为失败，仍能留在房间查看；主动退出会先认输再离开。短暂断线不判负，开局后不能移除别人的席位。
- 联机模式禁用单方悔棋与重开；多个房间完全隔离。
- 联机魏方默认保持标准棋盘方向；蜀、吴默认显示相同的 180° 视角，刘备子力在屏幕下方左侧、孙权子力在下方右侧。任何视角都能手动翻转，点击与触摸会换算回同一标准坐标，棋谱和服务端局面不随视角变化。
- 大厅可输入房间号观战等待中或已开局的房间；观战不占席位，不参与准备和行棋。观战者刷新、断线后重新取得完整公开局面，可以翻转视角或退出观战。

## 本轮范围与临时约定

联机房间和进行中的棋局只保存在服务器内存中，服务器进程重启后房间会丢失；账号、登录会话与已经结束的联机对局历史写入持久 SQLite。当前没有自动匹配、积分、得分率、排行榜、收藏、完整战绩统计、聊天或后台管理页面。大厅只展示维护者公开的房间摘要，不提供全服搜索。

棋盘等待层中，三人须全部在线、阵营不同且开始后才会开局。首次创建请自行输入 6 位数字房间号，例如 `001234`；如果已被占用，请换一个号码。房间号显示、邀请链接、地址栏和本机重连凭证均使用服务端确认的同一编号；换房前请先退出当前房间。结束后可在原房间直接再来一局；每局重新准备，阵营可在准备时调整。

观战者在“观战”入口输入相同的 6 位房间号即可进入，满员房间也可以看。观战页面显示玩家在线情况；开局后显示同步棋盘、轮次、上一手、棋谱和胜负。观战者不持有玩家重连凭证，也不能进行玩家操作。房间最后一名玩家退出后房间销毁，观战页面会提示返回大厅。

公开大厅只向订阅客户端广播最多 10 桌的摘要，并在房间变化后合并到约 50 毫秒一次更新。摘要不包含棋局、重连凭证或玩家内部 ID；大厅显示的可加入状态与服务端使用同一房间容量判断，席位选择也由服务端原子确认，因此最后一个空位或同一阵营席位不会被重复占用。公开桌在桌面无人时自动恢复为空桌，不需要提前创建。昵称可以留空，服务端会生成“游客”显示名。

### 以后新增歌曲

1. 将维护者提供的真实 MP3 放进 `public/audio/`，文件名使用小写字母、数字和连字符，例如 `new-song.mp3`。不要替换旧文件而沿用旧缓存标识。
2. 在 `src/music-catalog.ts` 添加曲目。曲目 `id` 必须稳定且唯一；歌曲 `file` 写文件名，`cacheVersion` 写该 MP3 的 SHA-256 前 12 位；PowerShell 可运行 `(Get-FileHash public/audio/new-song.mp3 -Algorithm SHA256).Hash.Substring(0,12).ToLower()`。换音频文件时同步更新该值，浏览器会通过版本参数获取新文件。当前设置页固定展示主题曲和“试听”按钮；恢复多曲目时再同步增加选择控件。
3. 运行 `npm test`、`npm run check`、`npm run build`。构建会检查每首配置歌曲确有对应文件、歌单有效及缓存版本与文件内容一致，并复制音频到 `dist/audio/` 和 `preview/audio/`。部署时上传完整包，不要漏掉新增 MP3。

旧浏览器保存的音乐开关和音量继续沿用，并默认选《流觞曲水》。已保存歌曲下架时回退到同歌单可用曲目；歌单也不存在时回退到第一个可用歌单。

**临时采用“吃主公判出局”模式。** 不强制应将，也不禁止送将；没有对面笑杀法。该模式是为了先验收棋盘与已明确的走法，不能视作作者已经确定的最终规则。

重复和棋的次数、三方重复局面的处理，以及应将、送将、将死的判定时点仍待作者确认。本轮不自动判重复和棋。详细规则与精确初始坐标见 [规则与初始坐标](docs/规则与初始坐标.md)。

## 账号、会话与数据

账号数据与房间数据分开保存：账号和登录会话写入 SQLite，重启 Node.js 后仍保留；房间、棋局和观战关系仍只在内存中，重启服务后房间丢失。

默认配置：

| 环境变量 | 本地默认值 | 说明 |
| --- | --- | --- |
| `THREE_CHESS_DATA_DIR` | `./.data` | 持久数据目录；数据库文件为 `auth.sqlite` |
| `THREE_CHESS_COOKIE_SECURE` | 非生产为 `0` | 生产环境应设为 `1`，只通过 HTTPS 发送 Cookie |
| `TRUST_PROXY` | `0` | 位于 Nginx 后时设为 `1`，用于取得真实客户端 IP 限流 |
| `HOST` | `127.0.0.1` | Node.js 监听地址 |
| `PORT` | `3000` | Node.js 监听端口 |
| `THREE_CHESS_REGISTER_LIMIT` | `20` | 同一 IP 在注册窗口内允许的注册请求数 |
| `THREE_CHESS_REGISTER_WINDOW_MINUTES` | `60` | 注册限流窗口分钟数 |
| `THREE_CHESS_LOGIN_LIMIT` | `10` | 同一 IP 与用户名的登录尝试上限 |
| `THREE_CHESS_LOGIN_WINDOW_MINUTES` | `15` | 登录限流窗口分钟数 |

生产配置写在 [systemd 服务](deploy/three-chess.service) 中：数据库目录为 `/opt/three-kingdoms-chess/data`，Cookie 仅通过 HTTPS 发送。该目录位于 `releases/` 和 `dist/` 之外，重新构建或切换版本不会覆盖。部署前须由 root 创建并授权：

```sh
sudo install -d -o www-data -g www-data -m 0700 /opt/three-kingdoms-chess/data
```

数据库连接时按 `user_version` 自动迁移到版本 `4`，保留已有 `auth_users` 和 `auth_sessions`。当前表包括 `auth_users`、`auth_sessions`、`game_records`、`game_participants` 及索引；`auth_users.avatar_data` 保存经过服务端格式与大小校验的头像数据。旧恢复码字段继续保留以避免重建账号表，但当前版本不再提供恢复码生成、查询或找回密码接口。密码使用 Node.js 成熟 `scrypt` 加盐哈希；Cookie 令牌只在数据库中保存摘要，范围限制为 `/three-chess`、`HttpOnly`。网页 Cookie 使用 `SameSite=Lax`，白名单 Android 来源使用 `SameSite=None; Secure`；生产环境网页 Cookie 也附加 `Secure`。密码、Cookie 和服务端会话令牌不写入 `localStorage`。

登录、注册和改密按服务端固定窗口限流；注册默认允许同一公网 IP 在一小时内发起 20 次请求，以兼顾校园、宿舍和共用设备，同时仍限制短时间批量注册。限流窗口和上限可通过环境变量调整，不使用浏览器指纹或“一 IP 一账号”。当前功能包含账号、固定昵称、会话和两种玩法的最近 5 盘目录，不含积分、得分率、排行榜、收藏或后台管理。

每盘历史对局只保存一份完整记录，通过 `game_participants` 关联参与的多个账号；`game_records.game_type` 区分三国象棋和迷雾象棋，旧记录迁移后仍归属三国象棋。开局即生成独立 UUID 对局 ID，同一房间“再来一局”使用新的局次与对局 ID；`(room_code, room_round)` 唯一约束防止重复结束生成多条记录。记录包含开始/结束时间、房间号、规则版本、初始局面、参与者用户 ID 与当时昵称、阵营、完整走法、认输/退出/超时/吃将等真实终局事件、终局原因、最终局面及各方结果。未正常结束并散房的房间不进入历史，不会补写上线前的虚构战绩。

备份和恢复详见 [账号系统与数据备份](docs/账号系统.md)。
